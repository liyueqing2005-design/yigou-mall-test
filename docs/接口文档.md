# 易购商城后端接口文档

## 一、基本信息

- **基础地址（Base URL）**：`http://localhost:8080/api`
- **服务端口**：`8080`（见 `application.yml`）
- **数据格式**：请求体与响应体均为 `application/json`（AI 流式接口为 `text/event-stream`）
- **统一响应结构** `ApiResult<T>`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 状态码，`200` 表示成功，`500` 表示业务失败 |
| `message` | string | 提示信息，成功为 `success`，失败为具体错误描述 |
| `data` | T | 业务数据，失败时为 `null` |

示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

- **全局异常处理**：`GlobalExceptionHandler` 捕获所有异常，返回 `code=500`，`message` 为异常信息。

---

## 二、枚举约定

| 枚举 | 取值 | 说明 |
| --- | --- | --- |
| 用户角色 `role` | `BUYER` / `SELLER` / `ADMIN` | 买家 / 卖家 / 管理员 |
| 商品状态 `status` | `ON_SALE` | 在售 |
| 订单状态 `status` | `PAID` / `SHIPPED` / `REFUNDING` / `REFUNDED` | 已支付 / 已发货 / 退款中 / 已退款 |
| 售后类型 `type` | `REFUND` / `RETURN_REFUND` / `EXCHANGE` | 仅退款 / 退货退款 / 换货 |
| 售后状态 `status` | `PENDING` / `APPROVED` / `REJECTED` / `APPEALED` / `REFUNDED` | 待处理 / 已同意 / 已拒绝 / 已申诉 / 已退款 |
| AI 场景 `scene` | `shopping` / `afterSale` | 导购 / 售后 |
| AI 角色 `role` | `user` / `assistant` | 用户 / 助手 |

## 三、用户认证模块（/auth）

### 1. 登录

- **请求**：`POST /auth/login`
- **请求体**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `username` | string | 是 | 用户名 |
| `password` | string | 是 | 密码 |

```json
{ "username": "buyer", "password": "123456" }
```

- **响应** `data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | long | 用户 ID |
| `username` | string | 用户名 |
| `nickname` | string | 昵称 |
| `role` | string | 角色 |
| `token` | string | 演示 Token（`demo-token-{id}`） |

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "username": "buyer",
    "nickname": "易购买家",
    "role": "BUYER",
    "token": "demo-token-1"
  }
}
```

- **失败**：账号或密码错误，`code=500`，`message=账号或密码错误`。

### 2. 查看演示账号

- **请求**：`GET /auth/demo-accounts`
- **响应** `data`：账号列表，每项含 `role`、`username`、`password`、`desc`。

## 四、商品模块（/products）

### 1. 商品列表

- **请求**：`GET /products?keyword=&category=`
- **查询参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `keyword` | string | 否 | 搜索关键词（模糊匹配名称/分类/品牌/店铺/标签/描述） |
| `category` | string | 否 | 分类精确过滤 |

- **响应** `data`：`Product[]`（仅返回 `ON_SALE` 状态，按销量、评分倒序）。

`Product` 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | long | 商品 ID |
| `sellerId` | long | 卖家 ID |
| `sellerName` | string | 店铺名称 |
| `name` | string | 商品名称 |
| `category` | string | 分类 |
| `brand` | string | 品牌 |
| `price` | decimal | 价格 |
| `stock` | int | 库存 |
| `sales` | int | 销量 |
| `rating` | decimal | 评分 |
| `coverImage` | string | 封面图 |
| `tags` | string | 标签（逗号分隔） |
| `description` | string | 描述 |
| `status` | string | 状态 |
| `createdAt` | datetime | 创建时间 |

### 2. 热销商品

- **请求**：`GET /products/hot`
- **响应** `data`：销量最高的前 12 个在售商品。

### 3. 商品详情

- **请求**：`GET /products/{id}`
- **响应** `data`：`Product`。

### 4. 新增商品

- **请求**：`POST /products`
- **请求体**：`Product`（`id` 自增；`status`、`sales`、`sellerId`、`sellerName`、`createdAt` 缺省时由后端填充默认值）。
- **响应** `data`：保存后的 `Product`。

### 5. 编辑商品

- **请求**：`PUT /products/{id}`
- **请求体**：`Product`（按 `id` 更新）。
- **响应** `data`：更新后的 `Product`。

### 6. 删除商品

- **请求**：`DELETE /products/{id}`
- **响应** `data`：`true`。

## 五、购物车模块（/cart）

### 1. 购物车列表

- **请求**：`GET /cart?userId=1`
- **响应** `data`：`CartItem[]`。

`CartItem` 字段：`id`、`userId`、`productId`、`productName`、`price`、`quantity`、`checked`、`coverImage`、`createdAt`。

### 2. 加入购物车

- **请求**：`POST /cart`
- **请求体**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `userId` | long | 否 | 默认 1 |
| `productId` | long | 是 | 商品 ID |
| `quantity` | int | 否 | 数量，默认 1 |

- **响应** `data`：`CartItem`。已存在同商品则累加数量，否则新建。

### 3. 修改数量

- **请求**：`PUT /cart/{id}`
- **请求体**：`{ "quantity": 3 }`
- **响应** `data`：`CartItem`。

### 4. 勾选/取消勾选单条

- **请求**：`PUT /cart/{id}/checked`
- **请求体**：`{ "checked": false }`
- **响应** `data`：更新后的 `CartItem`。

### 5. 全选/取消全选

- **请求**：`PUT /cart/check-all`
- **请求体**：`{ "userId": 1, "checked": true }`
- **响应** `data`：更新后的 `CartItem[]`。

### 6. 删除购物车项

- **请求**：`DELETE /cart/{id}`
- **响应** `data`：`true`。

### 7. 清空购物车

- **请求**：`DELETE /cart?userId=1`
- **响应** `data`：`true`。

## 六、订单模块（/orders）

### 1. 订单列表

- **请求**：`GET /orders?userId=1`
- **响应** `data`：`MallOrder[]`（含 `productSummary` 字段，如 `商品名 x数量；…`）。

`MallOrder` 字段：`id`、`orderNo`、`userId`、`receiverName`、`phone`、`address`、`totalAmount`、`status`、`createdAt`、`productSummary`。

### 2. 卖家订单

- **请求**：`GET /orders/seller?sellerId=2`
- **响应** `data`：`Map[]`，每项含 `orderId`、`orderNo`、`buyerName`、`phone`、`address`、`status`、`createdAt`、`productName`、`price`、`quantity`、`amount`。

### 3. 订单详情

- **请求**：`GET /orders/{id}`
- **响应** `data`：`{ "order": MallOrder, "items": OrderItem[] }`。

`OrderItem` 字段：`id`、`orderId`、`productId`、`sellerId`、`sellerName`、`productName`、`price`、`quantity`。

### 4. 结算下单

- **请求**：`POST /orders/checkout`
- **请求体**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `userId` | long | 否 | 默认 1 |
| `receiverName` | string | 否 | 默认「易购买家」 |
| `phone` | string | 否 | 默认 `13800000000` |
| `address` | string | 否 | 默认实训基地地址 |

- **逻辑**：结算购物车中 `checked=true` 的商品，生成订单（状态 `PAID`），写入订单明细并清空购物车。
- **响应** `data`：`MallOrder`。

### 5. 修改订单状态

- **请求**：`PUT /orders/{id}/status`
- **请求体**：`{ "status": "SHIPPED" }`
- **响应** `data`：更新后的 `MallOrder`。

### 6. 经营数据分析

- **请求**：`GET /orders/analysis`
- **响应** `data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `orderCount` | int | 订单总数 |
| `gmv` | decimal | 成交总额 |
| `avgOrderAmount` | decimal | 客单价（保留 2 位） |

## 七、售后模块（/after-sales）

### 1. 售后列表

- **请求**：`GET /after-sales?userId=&sellerId=&status=`
- **查询参数**（均可选，可组合）：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `userId` | long | 买家 ID |
| `sellerId` | long | 卖家 ID |
| `status` | string | 售后状态 |

- **响应** `data`：`AfterSaleRequest[]`。

`AfterSaleRequest` 字段：`id`、`afterSaleNo`、`orderId`、`orderNo`、`userId`、`buyerName`、`sellerId`、`sellerName`、`productId`、`productName`、`type`、`reason`、`description`、`status`、`result`、`createdAt`、`updatedAt`。

### 2. 发起售后

- **请求**：`POST /after-sales`
- **请求体**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `orderId` | long | 是 | 订单 ID |
| `userId` | long | 否 | 默认 1，需与订单买家一致 |
| `type` | string | 否 | 默认 `REFUND` |
| `reason` | string | 否 | 默认「七天无理由」 |
| `description` | string | 否 | 默认描述 |

- **逻辑**：校验订单存在且属于该用户，创建售后单（状态 `PENDING`），订单状态改为 `REFUNDING`。
- **失败**：订单不存在 / 只能申请自己的订单售后，`code=500`。
- **响应** `data`：`AfterSaleRequest`。

### 3. 联系平台客服（申诉）

- **请求**：`PUT /after-sales/{id}/appeal`
- **请求体**（可空）：`{ "userId": 1 }`
- **逻辑**：仅 `REJECTED` 状态可申诉，改为 `APPEALED`。
- **失败**：售后单不存在 / 只能申诉自己的售后单 / 非被拒绝状态，`code=500`。
- **响应** `data`：`AfterSaleRequest`。

### 4. 处理售后

- **请求**：`PUT /after-sales/{id}/process`
- **请求体**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `status` | string | 否 | 默认 `APPROVED` |
| `result` | string | 否 | 处理结果说明 |

- **逻辑**：更新售后状态，联动订单状态（`APPROVED→REFUNDING`、`REFUNDED→REFUNDED`、`REJECTED→PAID`）。
- **响应** `data`：`AfterSaleRequest`。

### 5. 售后数据分析

- **请求**：`GET /after-sales/analysis`
- **响应** `data`：`afterSaleCount`、`pendingCount`、`approvedCount`、`rejectedCount`、`appealedCount`、`refundedCount`。

## 九、AI 导购模块（/ai）

### 1. 智能问答（导购/售后）

- **请求**：`POST /ai/chat`
- **请求体**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `userId` | long | 否 | 默认 1 |
| `question` | string | 是 | 用户问题 |
| `scene` | string | 否 | `shopping`（默认）/ `afterSale` |

- **逻辑**：结合商品库、知识库（RAG）、订单/售后统计数据，优先调用通义千问（`DASH_SCOPE_API_KEY`），无 Key 或调用失败时回退本地模板回答。
- **响应** `data`：`string`（回答文本）。

### 2. SSE 流式问答

- **请求**：`GET /ai/stream?userId=1&question=...`
- **响应**：`text/event-stream`，`Flux<String>` 分段返回。

### 3. 历史记录

- **请求**：`GET /ai/history?userId=1&scene=shopping`
- **响应** `data`：`AiChatMessage[]`（MongoDB，最近 10 条）。

`AiChatMessage` 字段：`id`、`userId`、`role`、`scene`、`content`、`createdAt`。

### 4. 删除历史

- **请求**：`DELETE /ai/history`
- **请求体**：`{ "userId": 1, "ids": ["id1", "id2"] }`
- **响应** `data`：`true`。
